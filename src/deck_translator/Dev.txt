[DETERMINE DECK FORMAT TYPE]

If contains "[Main]" -> Forge.
Else -> Shandalar

Note: This is not sufficient to determine whether the card file is valid. If it cannot be parsed
properly later, error out.

[FORGE -> SHANDALAR]

INPUT: 1-6 Files
* Forge Deck
* vNone (Optional)
* vBlack (Optional)
* vBlue (Optional)
* vRed (Optional)
* vWhite (Optional)

OUTPUT: 1 File

Note: vNone must be included if vColor is used. If there is no corresponding vNone, vColor will be ignored.

CONSTRUCT HEADER

File header will take form of <Name> (<Color Identity>), e.g. "Lord of Fate (B/W").

To construct the header, name is grabbed from forge meta data (name field). Colors are added to a set while
the deck is constructed and used to define the color identity.

CONSTRUCT DECK LIST

Deck list can be derived from understanding each format's syntax:

Shandalar Format: .<id> <quantity> <name_optional>
Forge Format: <quantity> <name>|<expansion_scryfall_code>|<card_version>

1. To get ID, search card name in Shandalar Card List.csv and then pull ShandalarID field from that row.
   Helper function must be written to guarantee that name matches an actual Shandalar entry.
   Consider algorithms to handle strange and ambiguous formatting.
2. Quantity derived from Forge Format quantity.
3. Name derived from forge format name.

CONSTRUCT SIDEBOARD

Shandalar supports up to three sideboard cards which are selected based on the opponent's color.

If a color file is provided with three cards, it will be used to generate the sideboard section
at the bottom. vNone will be removed from the original decklist (constructed in the section above)
if there is a vNone file and a relevant vColor file.

For example, if the deck contained 4 Swamps and 4 Hypnotic Spectres, but vNone listed 1 Swamp and 2 Hypnotic Spectures, 
then the actual deck list would contain just 3 swamps and 2 Hypnotic Spectres.

[SHANDALAR -> FORGE]

INPUT: 1 File
OUTPUT: 1-6 Files (Mirrors Forge -> Shandalar)
 
CONSTRUCT HEADER

File header will take form of [metadata] /n Name=<Name>.

Name can be parsed from the first line of the Shandalar deck. If none, leave name field blank.

CONSTRUCT DECK LIST

Deck list can be derived from understanding each format's syntax:

Shandalar Format: .<id> <quantity> <name_optional>
Forge Format: <quantity> <name>|<expansion_scryfall_code>|<card_version>

1. Quantity is derived from Shandalar quantity.
2. To get name, search the id in Shandalar Card List.csv and pull the relevant CARD NAME field.
   Helper function must be written to guarantee that name matches an actual Forge card.
   Consider algorithms to handle strange and ambiguous formatting.
3. Scryfall code is pulled from the SET field in Shandalar Card List.csv, but a helper function
   must translate the set into a scryfall code (e.g. "Homelands" -> "HML").
4. Card version is always 1.

CONSTRUCT SIDEBOARD

Forge does not use sideboard files, but files can still be generated to translate back to
Shandalar format later.

Each sideboard field is constructed as an additional three card deck in Forge format.

vNone is added to Forge's main deck file as well.

CONSTRUCT SUBSECTIONS

Avatar, Planes, Schemes, Conspiracy, Dungeon, Attractions, and Contraptions are all appended but left empty.
